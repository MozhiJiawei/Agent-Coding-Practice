## 三、差异总结与结论

### 3.1 数据层面

- **规模与分布**：三个 YAML 在“地标数、房源数、各 House 字段取值与分布、Tags 语义分类、Landmarks”上**完全一致**，可视为同一套逻辑数据在不同平台下的 mock 或同一数据源导出的不同副本。
- **文件层面**：仅存在**文件体积**上的小幅差异（约 16–27 KB），更可能来自 YAML 序列化或键顺序等格式差异，而非房源/地标条数或字段取值的差异。

### 3.2 平台含义（按命名推断）

- **final-test**：基准/通用 mock 数据。  
- **final-test_58**：面向 58 同城 的 mock。  
- **final-test_LJ**：面向链家 (LJ) 的 mock。  

当前统计表明：**58 与链家两份数据在统计维度上与基准一致**，适合作为多平台一致性测试或对比测试的基线；若后续需要体现“平台差异”，需在数据源或生成逻辑上引入不同规则（如不同小区、价格带、标签体系等）。

### 3.3 建议

1. **测试与回归**：三份数据在统计上等价，可任选其一做规模与分布相关的回归测试；若需区分平台，建议在用例或标签上区分（如 `platform: 58` / `platform: LJ`），而不是依赖当前数据内容差异。  
2. **后续差异化**：若产品上 58 与链家应有不同（如房源数、区域分布、标签体系），需要在 `extract_mock_data.py` 或上游数据源中为不同平台配置不同规则或数据源，再重新生成 final-test_58 / final-test_LJ 并重新跑本统计与对比。
